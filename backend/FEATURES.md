# Edition split: community (CE) / enterprise (EE)

The mailez backend ships in two editions from one repository. The community
edition is the open-source webmail/console core; the enterprise edition adds
compliance, collaboration-at-scale, identity integration and AI. The split
is enforced by the compiler: EE code lives only under `backend/internal/ee/`
(plus paired `*_ee.go` assembly files), guarded by the `mailez_ee` build tag.

| Capability | CE | EE |
|---|---|---|
| Webmail, compose/outbox, contacts, sieve rules | ✓ | ✓ |
| Personal calendar + ICS feeds, personal drive | ✓ | ✓ |
| Admin console (domains, users, branding, config) | ✓ | ✓ |
| External account aggregation (fetch), push/SSE | ✓ | ✓ |
| CardDAV/CalDAV personal sync, invite links | ✓ | ✓ |
| LDAP/AD directory sync (login + address book) | ✓* | ✓ |
| Delegation (授权代发/代管) | | ✓ `internal/ee/delegation` |
| Announcements (公告) | | ✓ `internal/ee/announcement` |
| Compliance archive (audit + retention) | | ✓ `internal/ee/archive` |
| DLP (敏感词/审批 outbound filter) | | ✓ `internal/ee/dlp` |
| AI assistant (providers + chat) | | ✓ `internal/ee/ai` |
| ActiveSync | | ✓ `internal/ee/activesync` |
| S/MIME (certs, sign/encrypt) | | ✓ `internal/ee/smime` |
| Macro scanner (attachment VBA analysis) | | ✓ `internal/ee/macro` |
| Legacy-stack agent (legacy MTA/IMAP stack/nginx, migration + bench) | | ✓ `cmd/mailez-agent` |

\* LDAP stays in CE for this pass — its wiring reaches `core.App` and the
stack handler; moving it needs an interface seam and is scheduled as
follow-up work. Calendar/drive stay CE-side as mixed packages (personal
features are community; shared/team features need a package-level split
before they can move).

Rules (same contract as the mailezine engine):

- The CE dependency graph must never reach `backend/internal/ee`
  (`make check-ce-purity`).
- EE imports CE freely; CE reaches EE only through seams: the server-level
  `eeRegisterRoutes`/`eeStartComplianceWorkers` paired files, the compose
  `OutboundScanner` interface, and per-handler `*_ce.go` stubs
  (admin AI, user S/MIME).
- Degrade, never wedge: CE binaries warn "requires the enterprise edition"
  where configuration implies an EE capability; `cmd/mailez-agent` and
  `cmd/eas-e2e` print a clear error in CE builds.
- The public CE tree is generated by `scripts/export-ce.sh` at the repo
  root; it strips `backend/internal/ee/`, `*_ee.go`, `*_ee_test.go` and
  must build and test standalone.
