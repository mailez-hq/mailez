# mailez 功能测试提示词集（按功能模块）

> 用途：把每个模块的提示词直接交给一个 AI 测试代理（或 QA 工程师）执行。
> 用法：**先粘贴「〇、通用环境块」，再粘贴模块提示词**；每个模块建议独立会话/代理，互不污染。
> 配套基线：`qa/FUNCTIONAL-TEST-PLAN.md`（用例表 A1–H4）、`qa/qa-lib.psm1`（HTTP 会话封装）。
> 结果口径：只允许 PASS / FAIL / SKIP 三种结论，FAIL 必须附证据。

```text

- 后端 API：http://127.0.0.1:8081/api/v1（容器生产档）；若为本机 dev 直跑则为 http://localhost:8080。以实际监听端口为准（Get-NetTCPConnection -State Listen）。
- Webmail：http://localhost:8083（容器档）或 http://localhost:3001（next dev）
- 管理后台：http://localhost:8082（容器档）
- 2026-09-16 实测备注：当前 EE 容器栈 admin 实际映射为 http://127.0.0.1:18082/admin（base path `/admin`）；IMAP 143 广播 LOGINDISABLED（明文登录禁用，用 STARTTLS 或 993）
- 邮件协议端口：SMTP 25/465/587、IMAP 143/993、POP3 110/995、ManageSieve 4190（dev 直跑常用 SMTP 1587 / IMAP 143）

- 临时数据纪律：测试中创建的用户/域名/邮件一律用 qa- 前缀（如 qa-t1@example.com），结束后清理
- 环境自检命令：cd mailez/backend && go run ./cmd/e2e （发一封测试邮件并验证投递、DKIM 签名与防垃圾过滤）
```

## 〇²、统一输出要求（附在每个模块提示词末尾，不再重复）


## P2 · 认证与会话安全

```text
你是安全向的邮件系统测试专家。覆盖 mailez 认证与会话全链路（对照基线 A1–A8）：
1. 登录/登出：正确密码登录种下 HTTP-only 会话 cookie；错误密码 401 且不种会话；登出后 /sso/me 401。
2. 会话属性：cookie 属性核对（HttpOnly、Secure 按环境、SameSite）；Redis 滑动 TTL 生效（闲置后再操作仍有效、过期后失效）。
3. 密码：改密→旧密码失败→新密码成功→改回；弱密码/占位密钥在生产配置下拒绝启动（SECRET_KEY 弱值应 Fatal）。
4. 两步验证：TOTP 开启→登出→登录要求验证码→错误验证码拒绝→正确验证码通过→关闭 2FA；WebAuthn 注册与认证一遍。
5. 应用令牌：创建/列表/使用/吊销；吊销后旧令牌立即失效。
6. 登录限速：连续错误密码触发限速（记录阈值与锁定时长）；登录历史 /me/logins 包含本机登录记录。
7. 临时凭据边界（本系统特色）：webmail 会话换取的 token-* 短时凭据能过 IMAP/SMTP 认证；登出或会话失效后同凭据必须被拒；真实密码绝不出现在浏览器侧请求中（抓包核对）。
```

## P3 · 邮件收发端到端（核心主流程）

```text
你是邮件系统测试专家。覆盖收发主流程（对照基线 B6/B7 与 H1）：
1. 端到端发信：qa-用户 A 经 webmail/compose API 发给同域 B→B 收件箱出现该信（记录投递时延）。
2. 信头正确性：From/To/Message-ID/Date/Subject 与提交一致；本域发件人未伪造（Sender 校验拒绝代发他人地址，用目录契约 Sender 规则）。
3. 回复与转发：带 In-Reply-To/References 的回复被正确聚合成会话；转发保留原文引用。
4. 附件：带附件发信（小文本 + 接近 20MB 上限的大文件各一）→收件方能下载且字节一致（哈希比对）；超限附件被拒且有明确报错。
5. 密送 BCC：Bcc 收件人收到信；其他收件人看到的信头不含 Bcc（对照基线 B8 的已知回归点）。
6. 发件身份：identities 列表正确；用别名身份发信成功；用未授权地址发信被拒。
7. 异常路径：发给不存在的本域地址（应退信或进 postmaster 流程）、发给格式非法地址（应在提交时被拒）。
8. 多收件人（To+Cc 混合、10+ 收件人）：全员收到且各自信头正确。
```

### 执行纪律（所有模块共用）

1. 先 P1 冒烟，后功能；环境未就绪不出报告、不编造结果。
2. 每个结论必须有证据；无法验证的写 SKIP 并说明缺什么环境。
3. 测试数据一律 qa- 前缀，收尾清理并列清单。
4. 发现 P0（数据丢失、跨用户泄露、崩溃）立即上报，不等全部跑完。
5. 引擎侧并发/多活等非功能深水区（accountgate、kvlease、事务认领）不在本功能测试范围，另立专项。
