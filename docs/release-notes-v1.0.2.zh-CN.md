# Mailez v1.0.2 发布说明

**发布日期：** 2026年10月14日

此版本引入了多签名支持与组织页脚功能，优化了 Webmail 导航界面，并在安装、认证、会话管理、封禁归因和 MIME 处理方面提供了关键修复。

## 亮点

### 多签名支持与组织页脚

撰写邮件现在支持每个账户多个富文本签名（HTML 格式，附带纯文本备选），管理员还可以从管理控制台发布组织范围的页脚。当为发件人域名启用时，引擎会将页脚附加到外发邮件中。

### 导航界面优化

管理控制台入口从侧边栏底部的溢出菜单移至顶部标题栏（右上角，仅管理员可见），侧边栏底部将过滤规则显示为直接图标——完全消除了"…"溢出菜单，提供更简洁、更符合主流 Webmail 体验的界面。

### 安装与种子数据加固

- `install.sh` 现在在种子化 admin 账户失败时快速失败，而不是报告成功并留下警告，导致运行的栈没有 admin 账户
- Passkey 注册修复：用户句柄编码从 UTF-8 字符串切换为 WebAuthn 规范要求的 base64url，消除了非 UTF-8 字节上的 `atob()` 失败
- 镜像标签持久化修复：即使模板中被注释掉，`MAILEZ_IMAGE_TAG` 现在也会写入生成的环境文件，防止回退到 `:latest`
- Admin 种子 panic 解决：无论域名长度如何，`admin@<MAILEZ_DOMAIN>` 现在都能正确构造，并验证显式的 `MAILEZ_ADMIN_EMAIL`

### 认证与会话安全

- IMAP 开关强制加固：移除了端口 143 豁免，因此禁用 IMAP 会在所有端口立即生效（不仅是 993）
- 认证缓存作用域限定：真实凭证（密码/应用令牌）始终查询控制面板；只有 webmail 会话令牌被记忆，因此操作员更改会在下次登录时生效
- 禁用时断开会话：禁用账户或轮换凭证现在会通过管理 API 断开活动的 IMAP 会话，包括 AD/LDAP 同步禁用
- 封禁引擎归因修复：不可归因的来源（空 IP）不再创建锁定所有邮件协议的全局封禁；引擎现在在认证调用中提供连接客户端的地址

### MIME 处理

嵌套 `multipart/alternative` 在 `multipart/mixed` 内的消息——最常见的布局——现在能正确渲染。提取器会下降完整树结构，尊重每个部分的传输编码和字符集。

## 完整变更日志

### 新增

- 撰写支持多个富文本签名：账户维护签名列表（HTML 带纯文本备选），撰写面板为每封邮件选择一个。管理员还可以从管理控制台发布组织范围的页脚；当为发件人域名启用时，引擎将其附加到外发邮件

### 变更

- Webmail 导航界面：管理控制台入口从侧边栏底部的溢出菜单移至标题栏（右上角，仅管理员），侧边栏底部在图标行中将过滤规则显示为直接图标，因此"…"溢出菜单已消失

### 修复

- Web 推送在订阅或重启后错过第一条消息：通知器从账户的首次未读读取建立基线，因此在该读取之前到达的邮件被折叠到基线中且从未推送。投递回执现在直接宣布其收件箱副本，无需等待未读计数达成一致。垃圾邮件副本保持静默
- 转发丢失 HTML 格式和附件：撰写窗口以纯文本引用打开且没有文件，即使原始邮件有丰富的 HTML 和附件。两个转发入口点（`forward()` 和 `forwardFrom()`）现在优先使用原始 `html_body`（降级到纯文本）并携带源邮件的附件，镜像 `editDraft()` 恢复草稿的方式
- `install.sh` 在种子化 admin 账户失败时报告成功：失败被降级为 `seed failed (maybe already seeded)` 警告，导致运行的栈根本没有 admin 账户。失败的种子现在是失败的安装，附带在原因修复后重新运行的命令
- Passkey 注册在创建凭证之前就失败，错误为 `Failed to execute 'atob' on 'Window': The string to be decoded contains characters outside of the Latin1 range`。仪式配置为 `EncodeUserIDAsString`，将用户句柄放入 JSON 字符串，而 `WebAuthnID()` 返回 `sha256(email)` 的原始 32 字节：`encoding/json` 将每个非有效 UTF-8 的字节替换为 `U+FFFD`，webmail 的 `atob()` 拒绝结果。句柄现在以规范要求的 base64url 字符串离开（go-webauthn 的默认值），这正是 webmail 解码的格式
- `install.sh` 丢弃了镜像标签：它就地重写 `MAILEZ_IMAGE_TAG`，但 shipped 的 `mailez.env.example` 将该键保持注释状态，因此替换没有匹配任何内容，生成的 `deploy/mailez.env` 根本不携带标签，栈回退到拉取 `:latest`。`--tag` 和交互式提示现在会进入文件（结束摘要还将 admin 地址打印为 `admin@<MAILEZ_DOMAIN>`）
- `mailez-seed` 在 `MAILEZ_DOMAIN` 与默认 `admin@example.com` 一样长的部署上 panic，错误为 `slice bounds out of range [:-1]`：本地部分通过减去域名长度从电子邮件中切断，因此相等长度意味着负边界（任何其他不匹配静默写入错误的本地部分）。账户现在默认为 `admin@<MAILEZ_DOMAIN>`，并且该域外的显式 `MAILEZ_ADMIN_EMAIL` 会以命名两个值的消息停止
- 每用户"启用 IMAP"开关在端口 143 上静默无效：邮件认证端点豁免了在 webmail 端口到达的每个凭证，而 143 既是 webmail 的内部 IMAP 跳板，也是引擎向互联网发布的端口，因此邮箱密码或应用令牌在操作员为该账户禁用 IMAP 后仍能以完整 IMAP 客户端登录（开关仅在未公布的隐式 TLS 端口 993 上生效）。豁免现在仅涵盖 webmail 自己的短期 `token-` 会话凭证，并且不再查询监听器端口——引擎在同一端口上服务 webmail 和互联网，因此端口不能说明谁在连接
- 引擎的认证缓存在协议间重放成功：其键仅为凭证对，并且每个协议共享一个缓存，因此使用账户密码的单次认证 SMTP 提交让下一个 IMAP 登录通过而无需询问控制面板——为 `enable_imap` 关闭的账户重新启用 IMAP。真实客户端凭证（密码和应用令牌）现在始终前往控制面板，只有 webmail 的会话令牌——池化 IMAP/SMTP 拨号重新呈现的凭证——被记忆，因此操作员的更改也适用于下次登录，而不是一个 TTL 之后
- 禁用账户、关闭 IMAP/POP3 或轮换密码会让已打开的 IMAP 会话继续服务邮件，因为授权在登录时决定：控制面板现在告诉引擎（通过管理 API 上的 `POST /v1/accounts/{email}/disconnect`）在这些更改时断开账户的活动会话，包括离开目录的 AD/LDAP 同步禁用的账户。调用扇出到引擎服务解析到的每个地址，因为每个副本维护自己的会话表，单次调用只能到达其中一个
- 来自不可归因来源的大量失败登录锁定了每个邮件协议登录。封禁引擎按源 IP 跨 web 登录和邮件代理 SASL 网关统计失败次数，没有可解析地址的请求——其中包括引擎自己的服务到服务认证调用——被记录为空地址；该封禁行随后匹配每个其他不可归因的请求，因此二十次失败用 LIMIT 响应每个 IMAP/SMTP/POP3 登录（webmail 在每个文件夹上显示服务错误），升级阶梯在客户端持续重试时保持封禁活跃。不可归因的来源不再是封禁主体，引擎现在在认证调用中提供连接客户端的地址，因此封禁再次归因于真实来源
- MIME 树在 `multipart/mixed` 内嵌套 `multipart/alternative` 的消息——大多数邮件客户端发出的布局——以空白正文渲染：正文提取遍历单级 multipart，因此嵌套的文本和 HTML 部分从未找到。提取器现在下降整个树，尊重每个部分自己的传输编码和字符集；附件、日历和字符集处理保持不变

## 升级说明

无数据库迁移或破坏性变更。现有部署将在下次重启时自动获取新行为。

要使用组织页脚功能：
1. 导航到管理控制台 → 设置 → 组织页脚
2. 发布您的页脚内容（支持 HTML）
3. 根据需要为特定域名启用它

要配置多签名：
1. 转到 Webmail 设置 → 签名
2. 添加多个带有富文本编辑的签名
3. 为每个账户选择默认签名
